How to play

NeonCart Bug Hunt

A startup shipped an e-commerce platform written entirely by AI agents — fast, confident, barely reviewed. The code is released to you one module at a time. Your job: read it, run it, break it, and capture the flag the app produces. Some flags are reached through bugs in the code.

The loop

  1. Sign in to the portal

    Your facilitator gives you an account and the portal link. Use the email and password they provide; accounts are created by the admin.

  2. Wait for a module to open

    The admins release modules one at a time. When a module is released, its download opens for everyone. Each zip is the whole app at that stage — nothing to assemble.

  3. Download, unzip, run 
    unzip neoncart-v0.zip
cd neoncart-v0
PLAYER_SEED=your_seed_here node server.js

    Replace your_seed_here with your seed, or copy the complete command shown on the portal's Modules page. No install step is needed for the challenge app. Then open http://localhost:3307.

  4. Read the code, then use the app

    The nav bar at the top of the app is the app's own menu. Read the source in src/routes/ — every module is one file, and the bug is in there. Then try to trigger it from the browser.

    Module 00 is your warm-up: the storefront prints a build key — that is your first flag. Submit it and the loop is yours for the rest of the session.

  5. Capture the flag and submit it

    The flag is printed by the running app when your exploit works. It looks like FLAG{0123456789} — copy it into the flag box on the portal's Modules tab and press Submit.

There is no flag hidden in the code

Grep will not find it. The flag is generated by the running app, on a code path that only your exploit can reach — that is the whole point of the challenge.

Where to look when you are stuck

The log tells you what the server did

Three places, same content:

• the terminal the app runs in

• logs/app.log in the app folder

• http://localhost:3307/logs in the app

It prints what your input actually did — which keys were merged, which path was served, which branch ran.

Ask in the right order

1. Read the module's one file in src/routes/.

2. Re-read the request your browser sent (the log shows it).

3. Ask the facilitator for a hint — there is no penalty for asking.

4. Read the code again, slower. The bug is one line.

House rules

Flags are unique to your account, so sharing one is pointless and provable. Do not read other people's code or probe the portal or its backend. Work only with the challenge app you downloaded, and do not stress other players. Ask for hints early.

If something breaks

The app will not start

Use the PLAYER_SEED command shown in the portal, or replace the placeholder seed in config/player-license.json with your own seed from the portal.

Port already in use

Start it on another port: PORT=3308 node server.js and open that one.

Your flag is rejected

Copy it without the surrounding text — the flag is exactly FLAG{…}. Uppercase FLAG, braces included.

A released module still looks locked

Press that module's Refresh status button in the portal. The portal does not continuously refresh release status.

Play individually · flags are unique per player · be excellent to each other.
